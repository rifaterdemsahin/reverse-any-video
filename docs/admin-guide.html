🧭 Admin guide

Follow these steps in order. Each one says what to check before you go on. This page is for the owner only and holds no secret values.

📍 Step 1 · sign in

Open the admin area and sign in with your Azure account

Go to /admin. You are sent to Microsoft sign-in. Use info@deliverypilot.net. Only that account from the owner's tenant can open the admin area.

Check: the analyzer page opens. If you see "Admin sign-in is not set up yet", the admin app or the session secret is missing. See Step 8.

🩺 Step 2 · check the server

Health check

Open /healthz. Look for these values:

FieldShould beIf not
oktrueThe app is not running. Run fly logs --app reverse-any-video.
auth_requiredtrueThe access token is not set. See Step 3.
azure_storagetrueKey Vault or storage secrets are missing.
deepinfratrueStoryboard is off. Set DEEPINFRA_API_KEY on Fly. Everything else still works.
🔑 Step 3 · the access token

Keep the token for the analyzer

The analyzer and the jobs API need the access token. Paste it once into the Access token box in the server panel. The browser keeps it for next time.

If you have lost it, set a new one in your terminal. This replaces the old token:

TOKEN=$(openssl rand -hex 24) && fly secrets set --app reverse-any-video ACCESS_TOKEN=$TOKEN && echo "$TOKEN" | pbcopy && echo copied

Anyone with the token can start analyses, and each one costs money. Keep it out of chat and out of the repo.

🎬 Step 4 · run a sample video

Analyse the test video and download the output

  1. On the analyzer, paste the video link https://www.youtube.com/watch?v=KnqTiAXUH7M into the URL field.
  2. Click Fetch and analyze URL. The status line shows the server's progress.
  3. When it says Done, click Download all (.zip).

What a link gives: metrics.json, hyperframes_prompt.md and hyperframes_template.json. A link is never downloaded, so there are no shots, no EDL and no storyboard. Those need an uploaded video.

Check: the zip opens and holds those three files. If the job shows an error about YouTube asking you to sign in, the server needs cookies. That is in Settings.

🎞️ Step 5 · run an uploaded video

Get all five files

Upload a video file you have the right to analyse instead of a link. The job then gives the shot list, the EDL and, with the AI key, the storyboard. Source video and frames are kept in Azure under internal/<job_id>/ for you. They are never in the customer's zip.

🧾 Step 6 · check what happened

Progress and model prompts

Every job keeps two records in Azure, in its folder internal/<job_id>/:

  • progress.json: status, start and finish times, the error if any, and the log.
  • llm_trace.json: each prompt sent to a model, without image data, and each reply or error.

Open them in the Azure portal under the storage account dprevanyvideo, container reverse-any-video. The model replies are what the models returned. No hidden reasoning is recorded.

💳 Step 7 · payments (not ready yet)

Stripe test mode

Customers can sign in and see the packs, but credit cannot be added until Stripe is connected. In Stripe test mode:

  1. Copy the test secret key (starts with sk_test_). Set it on Fly as STRIPE_SECRET_KEY.
  2. Create a webhook endpoint to https://reverse-any-video.fly.dev/api/stripe/webhook for the event checkout.session.completed. Copy its signing secret (starts with whsec_) and set it as STRIPE_WEBHOOK_SECRET.
  3. Deploy with fly deploy --ha=false.

Keep the app in test mode until you have tested a full payment. A live key is refused unless STRIPE_ALLOW_LIVE=1 is set.

👤 Step 8 · customer sign-in

Test the account sign-in

Customers sign in on /account with their email. The app sends a link that works once and expires in 15 minutes. Sending needs the Gmail secrets in Key Vault and SESSION_SECRET on Fly.

Check: after you click the link, the account page shows the email and a balance of $0.00.

🛠️ Step 9 · admin sign-in setup

If the admin area says it is not set up

Create the admin app and store its secret, as in the setup message, then deploy. The app needs three secrets in Key Vault or on Fly: the admin client ID, the admin client secret and SESSION_SECRET.
